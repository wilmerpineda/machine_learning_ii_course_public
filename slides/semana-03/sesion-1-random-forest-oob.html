Punto de partida

La sesión anterior dejó dos palancas para reducir varianza:

\[ \operatorname{Var}(\bar f)= \rho\sigma^2+\frac{1-\rho}{B}\sigma^2. \]

  • Más árboles reduce el segundo término.
  • Menor correlación reduce el piso que permanece.

Pregunta de recuperación

Si todos los árboles reciben remuestras distintas, ¿por qué todavía pueden parecerse demasiado?

Porque las variables predictoras más fuertes suelen ganar los primeros cortes en casi todos los árboles.

Bagging

Para cada árbol \(b=1,\ldots,B\):

  1. tomar una remuestra bootstrap de tamaño \(n\);
  2. ajustar un árbol sobre esa remuestra;
  3. guardar su predicción \(\hat f_b(x)\);
  4. agregar por promedio o probabilidades.

Bagging perturba observaciones, no necesariamente la estructura de los cortes.

Random Forest

Random Forest añade una segunda fuente de diversidad:

  1. remuestra observaciones;
  2. en cada nodo ofrece solo \(m\) de las \(p\) variables;
  3. escoge el mejor corte dentro de ese subconjunto;
  4. repite hasta construir \(B\) árboles;
  5. agrega sus predicciones.

La aleatoriedad es local

max_features no selecciona una sola lista de variables para todo el árbol.

En cada nodo se sortea un nuevo conjunto candidato.

Esto permite que variables útiles, pero no dominantes, produzcan árboles diferentes.

Clasificación: ¿voto o probabilidad?

Podemos agregar etiquetas:

\[ \hat y(x)=\operatorname{modo}\{\hat y_1(x),\ldots,\hat y_B(x)\}, \]

o probabilidades:

\[ \hat p(x)=\frac{1}{B}\sum_{b=1}^{B}\hat p_b(x), \qquad \hat y(x)=\mathbb{1}[\hat p(x)\ge \tau]. \]

Promediar probabilidades permite estudiar y ajustar el umbral.

Hiperparámetros con papeles distintos

Parámetro Control principal
n_estimators precisión de la agregación y costo computacional
max_features diversidad y correlación entre árboles
max_depth complejidad de cada árbol
min_samples_leaf regularización local y suavidad
class_weight costo relativo de errores entre clases

Más árboles no implica más overfitting

Con árboles ya definidos por el mismo mecanismo:

  • aumentar \(B\) estabiliza el promedio;
  • el beneficio marginal disminuye;
  • el costo de memoria y cómputo aumenta;
  • no corrige sesgo, fuga ni cambio de distribución.

La complejidad individual sigue importando.

¿Qué queda fuera del bootstrap?

Para una observación concreta:

\[ P(\text{no elegida})= \left(1-\frac1n\right)^n\longrightarrow e^{-1}\approx0.368. \]

Cada árbol dispone de observaciones que no usó para ajustar: sus observaciones out-of-bag.

Predicción OOB

Para una observación \(i\):

  1. identificar árboles que no incluyeron a \(i\);
  2. obtener sus probabilidades para \(i\);
  3. promediarlas;
  4. aplicar una métrica sobre todas las predicciones OOB disponibles.

No es un nuevo conjunto de datos: es una estimación interna por remuestreo.

OOB no sustituye automáticamente a CV

  • Solo está disponible con bootstrap.
  • Cada observación recibe un número aleatorio de votos.
  • La estimación puede ser variable con pocos árboles o pocos datos.
  • No resuelve dependencia temporal o agrupamiento.
  • El ajuste de hiperparámetros repetido también puede optimizar indirectamente OOB.

Una trampa con la métrica

El caso de churn contiene aproximadamente 84 % de no churn.

Un modelo trivial puede tener accuracy alta y ser inútil para retención.

Por eso compararemos con:

  • balanced_accuracy como métrica principal;
  • recall y precision de churn;
  • matriz de confusión;
  • accuracy solo como referencia secundaria.

Diagnóstico de estabilidad

Dos promedios similares pueden ocultar:

  • distinta dispersión entre folds;
  • predicciones individuales inestables;
  • sensibilidad a la semilla;
  • errores concentrados en la clase minoritaria.

Reportar solo la media borra información importante.

Errores frecuentes

  • Comparar modelos con particiones diferentes.
  • Elegir hiperparámetros mirando test.
  • Presentar oob_score_ sin declarar su métrica.
  • Confundir importancia predictiva con causalidad.
  • Ajustar el umbral usando el conjunto final.

De lo técnico a la decisión

Un bosque puede mejorar la consistencia de una alerta de churn.

Pero la recomendación debe declarar:

  • qué error se prioriza;
  • cuánta variabilidad queda;
  • qué población representan los datos;
  • qué no puede inferirse causalmente.
