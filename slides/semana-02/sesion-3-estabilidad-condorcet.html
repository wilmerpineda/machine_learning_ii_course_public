Estabilidad y Condorcet

De la fragilidad individual a la agregación

Machine Learning II · Semana 2 · Sesión 3

Una observación incómoda

Entrenamos dos árboles con datos casi iguales.

  • Cambia el primer corte.
  • Cambian ramas completas.
  • Cambian importancias.
  • Algunas predicciones varían mucho.

El desempeño promedio puede parecer similar y la estructura ser totalmente distinta.

¿Qué significa estabilidad?

Un algoritmo es estable si pequeñas perturbaciones de los datos producen cambios pequeños en el modelo o sus predicciones.

Podemos medir estabilidad de:

  • métrica;
  • predicción individual;
  • estructura;
  • variable seleccionada;
  • explicación.

Por qué un árbol es sensible

  1. La búsqueda es voraz.
  2. Dos cortes pueden tener mejoras muy parecidas.
  3. Una pequeña perturbación cambia el ganador.
  4. Esa división redefine las observaciones de cada rama.
  5. El cambio se propaga recursivamente.

Sensibilidad no es solamente “mal MAE”

Un modelo puede tener:

  • MAE promedio aceptable;
  • gran dispersión entre muestras;
  • predicciones individuales inconsistentes;
  • reglas difíciles de defender.

La estabilidad es una dimensión adicional de calidad.

Bootstrap

Para una muestra de tamaño \(n\):

  1. seleccionamos \(n\) observaciones;
  2. muestreamos con reemplazo;
  3. algunas aparecen varias veces;
  4. otras quedan fuera;
  5. ajustamos un modelo por remuestra.

Cada remuestra representa una perturbación plausible.

Aproximadamente 63,2 %

La probabilidad de que una observación no sea elegida en \(n\) extracciones es:

\[ \left(1-\frac{1}{n}\right)^n\to e^{-1}\approx0.368 \]

Por tanto, una remuestra contiene aproximadamente:

\[ 1-e^{-1}\approx0.632 \]

de observaciones únicas.

Agregar en regresión

Con \(B\) árboles:

\[ \bar f(x)=\frac{1}{B}\sum_{b=1}^{B}f_b(x) \]

Los errores positivos y negativos pueden compensarse.

Promediar no elimina un sesgo compartido por todos.

Agregar en clasificación

Cada modelo vota:

\[ \hat y(x)=\operatorname{modo} \{\hat y_1(x),\ldots,\hat y_B(x)\} \]

También puede promediarse predict_proba y aplicar un umbral.

La segunda opción conserva más información.

Condorcet: intuición

Si cada votante:

  • tiene probabilidad \(p>0.5\) de acertar;
  • vota de forma independiente;

la probabilidad de que una mayoría acierte aumenta con el número de votantes.

Formulación binomial

Para \(B\) impar:

\[ P(\text{mayoría correcta}) = \sum_{k=(B+1)/2}^{B} \binom{B}{k}p^k(1-p)^{B-k} \]

Si \(p<0.5\), agregar votantes empeora la decisión.

Ejemplo

Con \(p=0.60\):

Votantes Mayoría correcta
1 0.600
3 0.648
11 0.753
101 cercana a 0.98

El resultado ideal depende críticamente de independencia.

El supuesto difícil

Los árboles entrenados sobre los mismos datos:

  • ven patrones parecidos;
  • prefieren variables fuertes;
  • cometen errores correlacionados.

Cien copias del mismo árbol equivalen a un solo árbol.

Varianza del promedio

Si cada árbol tiene varianza \(\sigma^2\) y correlación media \(\rho\):

\[ \operatorname{Var}(\bar f) = \rho\sigma^2+ \frac{1-\rho}{B}\sigma^2 \]

El segundo término disminuye con \(B\); el primero permanece.

Dos palancas

Para reducir varianza:

  1. aumentar el número de modelos \(B\);
  2. disminuir su correlación \(\rho\).

Bagging trabaja principalmente con remuestras.

Random Forest añadirá aleatoriedad en las variables candidatas.

¿Modelo débil?

En ensambles, “débil” no significa inútil.

  • Debe aportar señal.
  • Debe superar una referencia relevante.
  • Sus errores deben diferir de los de otros modelos.

Precisión individual y diversidad operan conjuntamente.

De árbol a Bagging

datos
├── bootstrap 1 → árbol 1 ┐
├── bootstrap 2 → árbol 2 ├→ promedio/voto
├── bootstrap 3 → árbol 3 ┤
└── bootstrap B → árbol B ┘

Bootstrap Aggregating = Bagging.

Qué Bagging no resuelve

  • Variables con fuga.
  • Objetivo mal formulado.
  • Métrica equivocada.
  • Cambio fuerte de distribución.
  • Sesgo compartido.
  • Interpretación causal indebida.

Agregar modelos no corrige un experimento defectuoso.

Comparar correctamente

Árbol individual y ensamble deben usar:

  • mismos datos disponibles;
  • misma partición final;
  • misma métrica;
  • mismo momento de predicción;
  • selección separada de evaluación.

Interpretabilidad

Un árbol individual ofrece reglas recorribles.

Un ensamble:

  • mejora estabilidad;
  • pierde una única estructura explicativa;
  • requiere resúmenes globales y locales;
  • traslada el compromiso entre desempeño e interpretación.

Antes del reto

El reto exige:

  1. detectar fuga;
  2. comparar tres complejidades;
  3. elegir con validación;
  4. consultar test una vez;
  5. comunicar una recomendación;
  6. explicar el puente a Bagging.

Preguntas de cierre

  1. ¿Qué puede variar aunque el MAE promedio no cambie?
  2. ¿Por qué ayuda el bootstrap?
  3. ¿Qué condiciones necesita Condorcet?
  4. ¿Por qué la correlación pone un límite?
  5. ¿Qué problema metodológico no arregla un ensamble?

Apéndice: derivación de la varianza

\[ \operatorname{Var}\left(\frac1B\sum_b f_b\right) =\frac{1}{B^2} \left[ B\sigma^2+B(B-1)\rho\sigma^2 \right] \]

\[ =\frac{\sigma^2}{B} +\frac{B-1}{B}\rho\sigma^2 \]

Para \(B\) grande, el límite es \(\rho\sigma^2\).

Apéndice: independencia frente a diversidad

La independencia exacta rara vez existe.

En práctica buscamos:

  • errores menos correlacionados;
  • muestras y variables diversas;
  • desempeño individual suficiente;
  • agregación estable.

“Diversidad” es una aproximación operativa al supuesto ideal.
