La paradoja del árbol

Un árbol puede seguir dividiendo hasta memorizar casos particulares.

  • Entrenamiento mejora.
  • La estructura crece.
  • Las hojas contienen menos evidencia.
  • Validación puede deteriorarse.

Ajustar mejor los datos conocidos no garantiza predecir mejor datos nuevos.

Tres regímenes

Régimen Entrenamiento Validación Lectura
Underfitting malo malo modelo rígido
Adecuado bueno bueno estructura útil
Overfitting excelente peor aprende ruido

La brecha entre entrenamiento y validación es evidencia, no una definición automática.

Sesgo y varianza

De forma conceptual:

\[ \mathbb E[(Y-\hat f(X))^2] =\text{ruido}+\text{sesgo}^2+\text{varianza} \]

  • Árbol pequeño: mayor sesgo, menor varianza.
  • Árbol grande: menor sesgo, mayor varianza.
  • La validación busca un compromiso empírico.

max_depth

Limita el número de decisiones encadenadas.

  • Reduce interacciones de orden alto.
  • Facilita lectura y visualización.
  • Puede impedir divisiones útiles en ramas específicas.

No mide directamente el número total de hojas.

min_samples_leaf

Exige evidencia mínima para estimar cada media local.

  • Suaviza predicciones.
  • Reduce hojas dominadas por casos individuales.
  • Puede ser más interpretable que limitar profundidad.

En regresión, una media basada en dos observaciones es frágil.

Otros controles

  • min_samples_split: evidencia mínima para intentar dividir.
  • max_leaf_nodes: presupuesto explícito de regiones.
  • min_impurity_decrease: mejora mínima exigida.
  • max_features: variables candidatas por división.

Cada parámetro restringe una dimensión distinta de complejidad.

Pre-poda

La pre-poda detiene el crecimiento durante el entrenamiento.

Ventajas

  • menor costo;
  • control simple;
  • evita ramas diminutas.

Riesgo

  • una mejora local pequeña puede habilitar divisiones posteriores valiosas.

Post-poda

La post-poda:

  1. construye un árbol grande;
  2. evalúa qué ramas aportan poco;
  3. elimina estructura;
  4. selecciona el subárbol mediante validación.

Primero permite explorar; después penaliza complejidad.

Riesgo costo-complejidad

\[ R_\alpha(T)=R(T)+\alpha|T_{\text{hojas}}| \]

  • \(R(T)\): error del árbol.
  • \(|T_{\text{hojas}}|\): número de hojas.
  • \(\alpha\): precio por cada hoja.

Interpretar ()

Valor de () Resultado esperado
0 árbol sin penalización
pequeño poda ramas de bajo aporte
grande árbol muy compacto

ccp_alpha no se elige mirando test.

Poda por eslabón más débil

Para una rama \(T_t\):

\[ \alpha_t= \frac{R(t)-R(T_t)} {|T_t|-1} \]

Mide cuánto error adicional cuesta eliminar las hojas descendientes.

La ruta de poda produce una secuencia anidada de subárboles.

Curva de validación

Una curva compara:

  • valor del hiperparámetro;
  • desempeño de entrenamiento;
  • desempeño de validación;
  • variabilidad entre particiones.

No basta con escoger el mínimo: debemos leer estabilidad y complejidad.

Validación temporal

TimeSeriesSplit respeta el orden:

Fold 1: [train] [valid]
Fold 2: [----train----] [valid]
Fold 3: [--------train--------] [valid]

Cada validación ocurre después de sus datos de entrenamiento.

¿Por qué no K-Fold aleatorio?

En datos temporales puede:

  • entrenar con observaciones posteriores;
  • ocultar cambios de nivel;
  • producir una estimación optimista;
  • responder una pregunta diferente a la operación futura.

La partición debe representar el uso previsto.

El pipeline vive dentro de CV

Pipeline([
    ("prep", ColumnTransformer(...)),
    ("model", DecisionTreeRegressor(...)),
])

En cada fold:

  1. aprende categorías y transformaciones con train;
  2. transforma validación;
  3. ajusta el árbol;
  4. evalúa sin contaminación.

Selección frente a evaluación

TRAIN
├── ajuste en folds
├── selección de hiperparámetros
└── reentrenamiento final

TEST
└── evaluación una sola vez

Si cambiamos el modelo después de ver test, test deja de ser final.

Incertidumbre entre folds

Dos configuraciones pueden tener MAE medio parecido pero distinta dispersión.

  • Media: desempeño esperado.
  • Desviación: sensibilidad al periodo.
  • Peor fold: riesgo operativo.

La mejor decisión no siempre es la diferencia decimal más pequeña.

Residuales

\[ e_i=y_i-\hat y_i \]

Buscar:

  • sesgo sistemático;
  • errores que crecen con la demanda;
  • días extremos;
  • segmentos con fallas recurrentes.

Una métrica agregada puede ocultar patrones.

Error frecuente: elegir dos veces

  1. Elegimos profundidad con CV.
  2. Miramos test.
  3. Cambiamos profundidad porque test “no gustó”.

El paso 3 incorpora test a la selección y vuelve optimista la evaluación.

Decisión metodológica defendible

Una justificación debe indicar:

  • espacio de configuraciones;
  • esquema de validación;
  • métrica principal;
  • criterio de selección;
  • uso único de test;
  • sensibilidad observada.

Apéndice: regla de un error estándar

Puede elegirse el modelo más simple cuyo desempeño esté dentro de un error estándar del mejor.

  • Sacrifica una mejora incierta.
  • Favorece parsimonia.
  • Requiere reportar variabilidad, no solo media.

Apéndice: complejidad no es solo profundidad

Dos árboles con igual profundidad pueden diferir en:

  • número de hojas;
  • distribución de casos por hoja;
  • variables usadas;
  • mejora total de impureza;
  • sensibilidad ante perturbaciones.
